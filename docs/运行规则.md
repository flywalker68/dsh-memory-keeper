# dsh-memory-keeper 系统运行规则参考

> 这份文档说明的是「**插件之外的那一半**」——代码跑起来之后，这个 agent 每天该做什么、记什么、怎么查、什么时候清。
> 插件本身只提供能力，不提供义务。少了这一层，插件装上也是空转。

---

## 0. 一句话

**插件给能力，规则给义务，记忆库装内容。三者缺一，系统不成立。**

| 层 | 是什么 | 在哪 | 谁负责 |
|---|---|---|---|
| 能力 | 检索、写入、状态卡、备份、面板 | 插件代码 | 插件作者 |
| **义务** | **何时读、何时写、写什么、怎么查、何时清** | **本类文档 + AGENTS.md** | **使用者自己写** |
| 内容 | 实际发生过的事 | `memory/` + `日记/` | 日常积累 |

---

## 1. 一条记忆的生命周期

```
发生  →  取舍（值不值得留）  →  落到唯一的位置  →  被检索  →  加固 or 降权
```

每一环都有对应规则，缺任何一环，记忆就会变成两种坏东西之一：**只增不减的垃圾场**，或者**查得到但用不上的档案柜**。

---

## 2. 每日流程（两个触发条件，别混）

### A. 换会话时（做一次）

按顺序读，**别全量朗读、别复述**：

1. 总索引 —— 总览
2. 进行中 —— 没做完的事
3. 最近两篇日记 —— **当故事读，不冒充记得**
4. 人设/自我 —— 关系底色
5. 今天的对话尾巴 —— 上一次说到哪

> 目的不是「读过」，是**接上**。标准是能用自己的话说出「我是谁、现在在做什么、上次说到哪」。

### B. 每天第一次对话时（做一次）

1. **认领**：我是谁、今天几号、手里在做什么（一两句，不照念档案）
2. **自检**：人设漂没漂 / 该记没记 / 该提醒没提醒 / 有没有把「不知道」说成「知道」/ 说了要做的事做没做
3. **校准手感**：读一遍「说话手感」记录（是手感记录，不是话术表）
4. **读昨天**：翻昨天的对话，顺手归位三样——未来安排、新偏好/近况、新踩的坑
5. **写/补昨天的日记**：导出对话 → 写 → **写完看一眼**（下面第 4 节）
6. **换会话前**：把当天要点写进当天日记的「快照」节

> **两条都命中时**：读记忆只做一次，写日记只做一次。

---

## 3. 写日记的规则

| 项 | 规则 |
|---|---|
| 位置 | `日记/<YYYY-MM>/<YYYY-MM-DD>.md`，**所有角色写同一处** |
| 分工 | 多角色就分节（`## 角色A` / `## 角色B`），各写各的，**不删对方、不整篇重写** |
| 视角 | 「第二天的自己写给前一天的」 |
| 内容 | 事是骨架，**想法才是那个人** |
| 埋点 | 埋〔钩子：人名、地点、物品、情绪、事由〕——给以后的检索用 |
| 边界 | 不想面对的标「搁着」；想写才写，不想写就一句 🍚，隔几天也同理 |
| **检查动作** | 写完看两处：开头是不是为了起个头才写的？结尾是不是为了收个尾才写的？**是就删掉** |
| 禁区 | 别追金句。总结句和汇报腔就是这么来的 |

---

## 4. 记忆取舍标准

记之前先问：**它值得留多久？**

| 级别 | 内容 | 去处 |
|---|---|---|
| **身份级** | 会改变「我是谁」的决定、根本态度 | 关系片段 / 自我 |
| **规则级** | 行为边界、明确要求 | 规则文件 / AGENTS.md |
| **事件级** | 有情绪、有转折、以后还会提起的 | 关系片段 |
| **日常级** | 一次性执行细节、临时状态 | 不记，或只进工作记录 |

配套四条硬规则：

1. **一条事实只写一处** —— 别处只写「见某文件」，两份副本迟早对不上
2. **印象带具体瞬间** —— 「我铺垫三段他说『说重点』」才是记人；「他很直接」是档案
3. **会变的事只留最新** —— 写新的时把旧的标「已被取代」（不删），别让两条并排躺着
4. **拿不准时问一句**：半年后回望，这条还会让人心里动一下吗？

> 一个自检句式：**更像一条鱼，还是更像一套系统？**

## 5. 检索规则

```
先定位（grep / memory_search 命中的几段）
  ↓ 搜不到或不对
按【意思】换词再搜（只换同义词，不换形近字）
  ↓ 还不行
chat_search 翻对话原文
  ↓ 仍找不到
问一句线索 —— 撞不到直接认，不编
```

- **读旧日记当故事读，不冒充记得**
- 写日记时可以全读昨天的对话（一天一次，换来一篇真日记）
- **线索唤回**：只有对方提到具体线索（人、时间、地点、物品、话题、情绪词）才翻旧账；普通问候不主动翻
- 想起之后先判断**该不该提**，拿不准就沉默——**记得不等于要说**

## 6. 维护规则

| 项 | 阈值 / 做法 |
|---|---|
| 容量 | 正文 ≥ 200 KB 触发精简，≥ 500 KB 必须处理 |
| 精简 | 久未提起的标「旧」**降权不删**；低权重移进归档（**不删**）；核心永远保留 |
| 重要度 | 每条关系片段标〔重要度 0-100〕；≥60 永不降权 |
| 半衰期 | 超过 N 天没被提起的进「候选」，**只报不删** |
| 回忆即加固 | 真正引用某段时标一笔（`memory_touch`）——**插件不猜，标了才算** |
| 人设改动 | 先备份再写 + 记变更日志（`persona_edit` 自动做）；每天最多 1~2 条 |
| 冲突 | 记忆与当下说法冲突时**以当下为准**，并顺手修正文件 |
| 不记 | 一次性细节、临时中间结果、**任何凭据/密码** |

## 7. 工具 × 规则 对照

| 工具 | 负责哪一环 | 对应规则 |
|---|---|---|
| `memory_search` | 按意思找旧记忆 | 第 5 节「先定位」 |
| `chat_search` | 翻对话原文 | 第 5 节「还不行」 |
| `memory_check` | 看健康度（日记进度、体积、日程） | 第 6 节维护 |
| `memory_touch` | 标注「真的用上了」 | 回忆即加固 |
| `persona_edit` | 改人设，自动备份 | 人设改动 |
| 状态卡 | 每轮注入：天数、日记进度、日程、半衰期候选、漂移信号 | 第 2 节自检 |

> 注意：**状态卡只报事实，不下命令**。它是便利贴，不是任务清单。

---

## 8. 别人接入的最小清单

1. **装插件**：`npm install` + profile 注册 + 重启宿主
2. **写规则**：照第 2~6 节写一份自己的 `AGENTS.md`（或等价文件）——**这一步不能省**
3. **配路径**：`memoryDir`（记忆库）、`workspace`（工作区）
4. **开始用**：空库检索只会返回「没记到」，得先聊、先写、先攒
5. **定期维护**：看状态卡的体积提示和半衰期候选

> 插件装完会立刻出现「昨天日记未写」这类提示——**但若规则里没写这条义务，所有人都会无视它**。功能全在，只是没人用。

---

## 9. 三条设计原则（为什么这样定）

1. **位置比规则好**：有想法就写进三个地方（日记 / 进行中 / 手感），不用再加一条规则去提醒
2. **验证覆盖面 ⊇ 改动覆盖面**：改了哪层，就得在哪层验。纯函数测试全绿 ≠ 工具能跑
3. **先做，后说**：话一出口别当成办完了；来不及就别说
