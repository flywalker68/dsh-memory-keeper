# 怎么用这套记忆库

插件只提供工具。**怎么用起来靠习惯**——这份是最小可用的日常流程，照做就能转起来。

> 这是**精简版**（快速上手用）。完整规则、取舍标准、逐条义务见 [`docs/运行规则.md`](../docs/运行规则.md)。两处不冲突：这份是「先跑起来」，那份是「跑得稳」。

## 每开一个新会话

1. 读 `12-进行中.md` —— 手头在做什么
2. 读最近一两篇日记 —— 昨天发生了什么
3. 读 `07-日程.md` —— 今天、明天有什么事

中间拿不准的，用 `memory_search` 搜；问「原话」用 `chat_search`。

## 每天结束前

1. **写今天的日记**：`日记/YYYY-MM/YYYY-MM-DD.md`
2. **更新 `12-进行中.md`**：手头剩什么、下一步做什么
3. **重要的事当天就记**，别攒——攒着攒着就忘了当时怎么想的

## 什么时候该记

| 记什么 | 记到哪 |
|---|---|
| 用户说过的重要的话 | `01-用户画像.md` |
| 关系里的**具体瞬间** | `13-重要记忆.md` 的关系片段 |
| 日程上的事 | `07-日程.md` |
| 手头正在做的 | `12-进行中.md` |
| 项目进展 / 技术坑 | `02-项目.md`、`04-环境经验.md` |

## 别记

- **一次性细节**（明天就没用的）
- **凭据、密码、密钥**
- **推测当事实**——拿不准就在句子里写「推测」「不确定」

## 什么时候清理

`memory/` 正文超过 **200 KB** 就精简一次：

- 旧条目归并
- 过期的标「旧」降权（**不删**）
- 真没用的移进 `archive/`（主库检索不扫它）

## 写关系片段的诀窍

最容易犯的错——**只写结论**：

```markdown
- 用户很信任我              ← 三个月后翻到这条，什么都想不起来
```

写成具体的事：

```markdown
- **2026-11-03** · 用户说「你不用每次都问我」
```

以后问「什么时候开始放手的」，能翻出这句原话。

## 一句话

**记忆库不是日志本，是会一直被读到的东西。**

写的时候问自己：三个月后翻到这一条，还有用吗？没用就别写。
